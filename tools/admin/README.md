# Редакторская панель (локальный инструмент)

Панель не входит в публичную сборку: на сайте нет ни одной ссылки на эти файлы, а `tools/`
не попадает на прод (см. список публикуемого состава в `tools/deploy-prod.sh`). Задача T-057:
редактор работает локально, посетитель сайта не видит ни формы с PIN, ни сбора ключей API.

## Как открыть

1. Запустить локальную копию сайта: `node tools/server.js` — адрес будет в логе (например,
   `http://127.0.0.1:8123`).
2. Открыть главную в браузере.
3. В консоли браузера (DevTools → Console) выполнить:

   ```js
   var s = document.createElement('script');
   s.src = '/tools/admin/loader.js';
   document.head.appendChild(s);
   ```

4. Дальше как раньше: `Ctrl+Shift+A` открывает панель, работают редактор каталога и ссылок.

Панель работает только на `localhost`/`127.0.0.1`: на боевом домене скрипты откажутся
запускаться, а в бандле нет ни PIN по умолчанию, ни входа по `?admin=1` и `/admin`.

## Что внутри

- `loader.js` — подключает `catalog.js` и `links.js`, проверяет, что хост локальный;
- `catalog.js` — редактор каталога и привязок статей (`data/catalog.js`);
- `links.js` — редактор партнёрских ссылок (`data/product-links.js`).

Правки живут в `localStorage` браузера до экспорта файла: панель сама ничего на сервер не
отправляет. Экспортированный файл кладите в `data/` и коммитьте как обычно.

## Чего здесь больше нет

AI-редактор с ключом Gemini отключён: ключ не читается и не сохраняется в `localStorage`
и не уходит в заголовке `x-gemini-api-key` на несуществующие `/api/gemini/*`. Код генератора
остаётся в бандле до production-сборки из исходников (T-028) — там его нужно вырезать совсем.
